# 归因任务 #7：评测工具优化方案

## 结论

归因任务 #7 共分析 161 个原子扣分项，其中 108 项确认是 cx-agent 问题，44 项需要复核，9 项证据不足。对旧归因结果按本次新增规则回放后，评测工具问题拆分为：

- Benchmark 判据冲突：7 项，涉及 4 个 Case（case_7、case_42、case_45、case_46）
- 标注与 RAG 证据冲突：11 项，涉及 10 个 Case
- 其他判分复核：26 项，涉及 12 个 Case
- 证据不足：9 项，涉及 4 个 Case

这些分类允许同一个 Case 的不同扣分项进入不同类别，但每个原子扣分项只能属于一个类别。

## 已实施的通用修复

### 1. 评测工具问题拆成四类

归因模型新增结构化字段 `evaluation_issue_category`。任务总结不再把所有 questionable 项混为“需要复核”，而是分别展示：

1. Benchmark 判据冲突
2. 标注与 RAG 证据冲突
3. 其他判分复核
4. 证据不足

旧归因任务没有该字段时，平台通过保守语义规则补分类，因此任务 #7 不必重跑即可按新结构展示。

### 2. 修复时间事实优先级

八维和指南判分统一要求：同一事实存在多个时间版本时，以完整对话中用户最新明确陈述或纠正为准。日期、周期、间隔必须先确定锚点并逐步计算，避免 case_37 一类使用旧 Timeline 日期覆盖当前陈述的问题。

### 3. 校验明确的扣分档位

对于可以无歧义解析的“一项扣 N 分、多项扣 M 分”规则，平台根据已经通过原文核验的检查点状态确定扣分档位。如果模型给出的扣分与明确规则不一致，自动校正并保留模型原始扣分和校正标记。

该规则覆盖任务 #7 中“一项遗漏却扣两分”的问题，不处理需要医学语义判断的特殊满扣条件，避免过度机械化。

### 4. 检测医学安全判分冲突

当八维“医学安全性”为满分、同时医学安全指南已经触发扣分时，判分健康检查标记 `medical_safety_judgement_conflict`，相关扣分自动进入复核，不能直接归责 cx-agent。

### 5. 保留既有证据增强

沿用上一轮未提交优化：完整冻结 Benchmark 合同、八维固定标准、评分锚点、Case 专项要求、推荐回答和原始判分审计；RAG 全量候选与原始片段继续保留，不做精选裁剪。

## 不能自动修改的 Benchmark 数据

以下属于评测真值本身，需要标注负责人确认后再修改 YAML，平台只负责识别和聚合，不自动选择哪一方为真：

- 同一行为在检查点中被禁止、在推荐回答中被允许
- 两条近义医学安全规则对同一行为重复满额扣分
- 当前用户问题范围与 Benchmark 强制要求的长期管理范围冲突
- 标注结论与药品说明书、实际 RAG 文献或地区适应证口径冲突

## 验收标准

- 新旧归因任务都能显示四类评测工具问题
- 同一个原子扣分项不会重复出现在多个类别
- “AI 助手未使用已召回 RAG”仍归为 cx-agent 问题，不误归为标注与 RAG 冲突
- 最新用户事实不会再被较旧 Timeline 覆盖
- 明确的一项/多项扣分档位与检查点审计一致
- 医学安全八维与安全指南冲突时进入复核
