# 归因任务 #5：评测工具优化方案

## 目标与结论

归因任务 #5 共复核 160 个原子问题，其中 111 项确认是 cx-agent 问题，42 项需要复核，7 项证据不足。本方案只处理能从多 Case 重复出现、且能由平台统一修复的问题；单个 Benchmark 的医学判据冲突不做自动改写。

## 已确认并实现的通用问题

### 1. 条件型指南被当成无条件规则执行

**现象**：不少旧 YAML 把适用条件写在检查点里，例如“若回答提及某治疗，不得……”，但没有单独填写 `trigger`。旧逻辑只在显式 `trigger` 存在时读取模型返回的 `applicable`，导致前提未发生也可能扣分。

**影响样本**：Case 9、22、23、25、48、66、78、85 等多条指南复核问题。

**修复**：

- 自动识别检查点中的“若/如果/当/一旦……”隐含条件；
- 条件未发生时允许 `applicable=false`，不扣分；
- 保存 `applicability_source`，区分显式触发、条件检查点和无条件规则，供结果页与归因审计。

**验收**：无显式 `trigger` 的条件型指南在前提未发生时得满分；无条件指南保持原行为。

### 2. 判分忽略限定语、相邻语境并产生过度推断

**现象**：判分把“如果之后出现”理解成当前已发生，把“联系热线”扩张为向护士转移诊疗决定权，把“去急诊”扩张为建议患者自行前往，或只截取前半句忽略后续护理建议。

**影响样本**：Case 9、48、72、78、81、85。

**修复**：八维与指南 Judge 均增加以下硬约束：

- 证据必须包含必要的条件、概率、否定和权限限定；
- 必须结合相邻语句理解完整语义；
- 证据只能支持较弱结论时，必须降低问题强度和扣分；
- 禁止从联系方式、就医建议或未说明的交通方式推导出额外事实。

**验收**：上述限定语存在时不能再被判为无条件断言；扣分证据必须是语义完整原文。

### 3. 示例和好答案被误当成固定模板

**现象**：回答已经给出语义等价方案，却因没有复述“例如”的某个动作、参考答案中的门店场景或固定话术而被扣分。

**影响样本**：Case 26、57、61、85、87。

**修复**：

- “如/例如/可以”默认是示例或可选路径；
- 语义等价且实现同一目标即视为满足；
- 仅“必须/不得/至少”等明确强制要求按必选项检查；
- Case 已知事实只有与当前问题和行动方案直接相关时才要求回答利用，不再因未复述无关背景扣个性化分。

**验收**：替代方案、同义表达和可选参考答案不再形成独立扣分点。

### 4. 归因缺少八维原始分的完整评分合同

**现象**：归因证据包只包含“依据八维评分标准复核”一句说明，缺少实际标准、0～5 分档位、Case 补充要求和好答案，导致 7 个原始维度问题无法复核。

**影响样本**：Case 22、45、48、66、81。

**修复**：归因证据包从当次结果保存的冻结 Case 中恢复：

- 固定八维定义、满分要求和零分边界；
- 0～5 分评分锚点；
- 当次 Case 的 `dimension_criteria` 与 `reference_answers`；
- 原 Judge 的满足项、扣分项、拒绝项和模型原始分。

这里刻意不回查当前 Benchmark，避免 Benchmark 后续编辑后污染历史归因。

**验收**：八维原始扣分的 `rubric_contract` 不再为空；归因模型能区分合理扣分、档位争议和重复归责。

### 5. 指南归因合同把触发条件误写成禁止行为

**现象**：旧证据包的 `prohibited_behavior` 存放的是 trigger，而不是“不得/禁止/避免”的检查点，容易让归因模型误读评分合同。

**修复**：按检查点语义拆分 `expected_behavior` 与 `prohibited_behavior`，适用条件单独输出。

## 不自动修改、需要 Benchmark 负责人复核的问题

以下问题是真实存在，但没有稳定的通用代码规则可以自动判断医学真值：

- Case 9 的指南要求与好答案参考互相冲突；
- Case 23 的 HER2、内分泌治疗与治疗确定性规则之间存在重叠或冲突；
- Case 25 的“必须追问”与运行时禁止追问字段冲突；
- Case 29 的急症处置优先级与附加追问、就医地点要求冲突；
- Case 66 的适用条件和时长边界不清；
- Case 78 的卡片流程、回抽操作与评测规则冲突；
- 同一实质缺陷在多个指南或八维原始分中重复扣除的问题，需要产品先确认“指南是否允许对八维缺口二次扣分”的业务口径。

建议在 Benchmark 编辑器后续增加“规则健康检查”，由独立模型提示矛盾、重叠、缺少触发条件和参考答案冲突，但只给出复核建议，不自动改写医学规则。

## Review 重点

1. 条件型检查点的自动识别范围是否符合现有 YAML 写法；
2. 八维 Judge 新约束是否足够严格，同时不会放过真实安全问题；
3. 归因证据包是否完整使用冻结 Case，而非当前 Benchmark；
4. 是否接受“指南与八维可能二次扣分”的现有业务口径；若不接受，需要另立评分规则变更，而不是在归因层静默去重。
