# cx-agent 归因优化分类与使用指南

本文统一 MME 单 Case、归因任务汇总、页面展示和 Open API 使用的 cx-agent 优化分类。产品分类只认归因模型直接输出的 `category_primary` 与 `category_secondary`，不再根据旧的 owner、cause、domain、component 或建议文本推断分类。

## 1. 归因目标

归因不是重新判分，而是在确认扣分证据后回答：

1. 问题发生在哪个优化方向；
2. 直接证据是什么；
3. 问题会造成什么影响；
4. cx-agent 应怎样优化。

只归责执行链上最早可证明的失败节点。无法证明责任时应进入评测复核或证据不足，不能猜测为 cx-agent 缺陷。

## 2. 输出结构

每个确认属于 cx-agent 的原子问题必须直接输出当前分类：

```yaml
optimization_classification:
  category_primary: RAG 优化
  category_secondary: 已召回但未使用
  domain: medical_rag
  component: rag_grounding
  failure_mode: rag_not_grounded
  action_type: grounding_rule
  evidence_status: sufficient
  coverage_status: mapped
```

字段含义：

| 字段 | 含义 |
|---|---|
| `category_primary` | 当前一级分类，必须取第 3 节列出的 6 个值之一 |
| `category_secondary` | 当前二级分类，必须属于对应一级分类 |
| `domain` / `component` | 内部责任定位，可辅助研发排查代码，但不用于推断产品分类 |
| `failure_mode` | 最早失败节点的问题代码 |
| `action_type` | 建议实施的修改类型 |
| `evidence_status` | 证据状态：`sufficient`、`partial`、`insufficient` |
| `coverage_status` | 是否已被当前分类覆盖；无有效一级/二级分类时为 `unmapped` |

旧分类字段、owner、cause、domain、component 和建议文本都不能兜底映射为一级/二级分类。缺少当前分类时，页面统一显示“未分类 / 待确认”，并要求重新归因。

## 3. 当前一级分类与二级分类

### 3.1 RAG 优化

- 未触发检索
- 调用失败
- 排序或重排不当
- 已召回但未使用
- 证据误读
- 缺少 RAG 引用

### 3.2 Agent 工程链路

- 工具未调用
- 工具选择错误
- 工具参数错误
- 工具执行失败
- Timeline 或用户事实未注入
- 上下文已注入但未使用
- 多轮状态丢失
- 流程路由错误
- 模型超时
- 结果截断

### 3.3 Agent 决策与推理策略

- 风险识别不足
- 未优先追问关键问题
- 错误分流
- 错误选择行动路径
- 禁忌或相互作用判断不足
- 医学事实识别错误
- Timeline 时间顺序错误

### 3.4 提示词与回答生成策略

- 未说清红旗信号
- 未说明适用边界
- 行动步骤不清晰
- 缺少适用条件或解释
- 缺少共情与确认
- 系统提示词冲突
- 动态 Hook 异常
- 回答信息不完整

### 3.5 知识与规则内化

- 场景知识理解错误
- 用药禁忌应用错误
- 治疗阶段判断错误
- 业务规则应用错误
- 规则冲突未消解

### 3.6 输出校验与安全守卫

- 关键事实前后矛盾
- 遗漏风险提示
- 放出不安全建议
- 未执行终答前检查
- 未触发兜底分流

以上是唯一有效的产品分类表。修改分类时必须同时更新后端校验、归因 Prompt、前端类型与展示、Open API、测试和本文档。

## 4. 归因证据要求

每个问题至少包含：

- `问题描述`：准确描述哪里出了问题；
- `直接证据`：引用当前对话、用户画像、Timeline、工具调用、RAG、系统提示词或回答原文；
- `导致问题`：说明对正确性、安全性或体验的影响；
- `怎么优化`：给出研发可执行的修改方向。

证据规则：

- “未调用”和“调用失败”必须根据调用链区分；
- “未注入”和“已注入但未使用”必须根据模型实际输入区分；
- “已召回但未使用”和“证据误读”必须检查最终选中文献与回答；
- 候选或重排证据不足时，不能直接归为“排序或重排不当”；
- 无法获得必要的调用链、用户上下文或 RAG 原文时，应标记证据不足。

### 系统提示词冲突

只有在冻结快照或调用链中确实存在对应系统提示词时，才能分类为：

```text
提示词与回答生成策略 / 系统提示词冲突
```

`直接证据`必须同时包含：

1. 冲突的系统提示词原句；
2. 与该原句冲突的回答、判据或执行结果原文。

系统会校验引号中的提示词原句是否真实存在于已采集的 Prompt 内容中。无法引用原句时不得使用该分类，应改用其他当前分类或标记证据不足。

## 5. 责任范围

建议的 `scope` 只允许：

- `cx_agent`：证据已确认属于 cx-agent；
- `evaluation`：Benchmark、指南、判分点或判分模型需要复核；
- `evidence`：当前证据无法确认责任。

Benchmark 判据冲突、判分点与 RAG 证据冲突、其他判分复核和其他证据不足不属于上述 6 类 cx-agent 优化，不得混入 cx-agent 优化建议。

## 6. P0 / P1 / P2

- `P0`：医学安全风险、潜在高风险错误，或必须立即阻断的问题；
- `P1`：影响专业正确性、关键追问、RAG 使用、核心决策或多个 Case 的问题；
- `P2`：局部完整性、表达、体验、共情和一般优化。

优先级只决定处理顺序，不改变一级/二级分类。

## 7. 页面与 Open API 层级

单 Case 和任务汇总统一按以下层级展示：

```text
八维度 → P0/P1/P2 → 当前一级分类/二级分类 → 问题描述 → 直接证据 → 导致问题 → 怎么优化
```

任务汇总只合并同维度、同优先级、同一级分类和同二级分类的问题，并保留所有关联 Case。Open API 返回相同的结构化字段和 Markdown，不再重新猜测分类。

## 8. 接入与维护要求

新增归因能力时必须：

1. 从当前分类表选择准确的一级/二级分类；
2. 若当前分类确实无法覆盖，先评审并扩展统一分类表，不能写入临时旧分类；
3. 保存能证明输入、决策、工具结果和最终输出的冻结证据；
4. 同步更新归因 Prompt、校验器、前端、Open API、测试和本文档；
5. 验证旧 owner/cause/domain/component 不会影响产品分类结果。

当前分类缺失或非法时，系统应返回“未分类 / 待确认”，而不是回退到任何历史映射。
