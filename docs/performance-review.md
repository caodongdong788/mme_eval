# MME 性能审查与优化记录

本轮检查覆盖 Web API、数据库访问、后台 Worker、评测结果聚合和前端轮询。原则是保持评分、权限、任务状态和返回数据口径不变，只减少不必要的 IO、循环、内存占用、锁竞争和数据库查询。

## 已定位并修复的瓶颈

| 类型 | 原瓶颈 | 优化结果 |
| --- | --- | --- |
| 数据库查询 | 每个有效 OpenAPI 请求先查询“是否存在任意 Key”，再按哈希查询当前 Key | 成功路径只保留一次 `key_hash` 唯一索引查询；仅错误路径补查平台是否尚未启用，HTTP 状态码保持不变 |
| 数据库写锁 | 每个 OpenAPI 请求都更新 `last_used_at`，高频调用持续制造写锁和 WAL | 按一分钟降采样；该字段只用于展示“最近使用”，不参与鉴权和业务判断 |
| 外部 IO / 锁 | 定时任务持有数据库事务及 PostgreSQL 行锁时请求 DeepTrace 版本，最慢可占锁 8 秒 | 外部请求移到事务和 `FOR UPDATE` 之前，远端延迟不再占用数据库连接和任务行锁 |
| 循环 / 数据库 | 取消归因任务时加载全部活跃归因 Job，再逐条解析 JSON payload 查找任务 | 使用 `active_key` 唯一索引直接点查，时间和内存复杂度由 O(n) 降为 O(1) |
| 内存 / 查询结果 | Case 列表审核摘要加载当前页所有历史审核对象，再在 Python 中分组取最新项 | 使用窗口函数在数据库内完成分组计数和最新项筛选，每个 Case 最多返回一条摘要 |
| 内存 | 待审核集合只需要 sample_id，却加载完整审核对象 | 改为数据库 `DISTINCT sample_id` 投影 |
| 内存 / JSON IO | 趋势接口加载完整 EvalRun，包括不参与展示的配置快照等 JSON | 使用列投影只读取趋势图需要的字段，并增加防止逐 Run 懒加载的查询数测试 |
| 前端 IO | 多个页面使用固定间隔轮询，慢请求可能重叠，后台标签页仍持续请求 | 统一为串行、可见性感知的轮询 Hook；上次请求结束后再计时，页面隐藏时暂停 |
| 列表 IO | Case 列表曾全量读取大型 `detail_json` 后在内存过滤分页 | 改为 SQL 过滤、计数、分页及标量列读取；完整 JSON 只在明细/导出路径加载 |

## 防回归约束

- OpenAPI Key 必须允许管理员在创建后随时查看完整值；优化不得恢复为“一次性展示”或只显示前缀。
- Key 管理端读取可恢复密文，普通 OpenAPI 鉴权只使用不可逆哈希，不能在高频路径增加解密操作。
- 定时任务发起期间不得在持有行锁时执行外部网络调用。
- Case 列表、趋势和审核统计不得触发逐行加载大 JSON 或 N+1 查询。
- 队列领取继续使用 PostgreSQL `FOR UPDATE SKIP LOCKED`，幂等与任务状态以数据库约束为最终准绳。

相关防回归测试集中在 `tests/server/test_perf_hardening.py`，全量前后端测试和生产构建也必须作为发布门禁。
