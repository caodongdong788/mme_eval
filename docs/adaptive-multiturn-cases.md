# 动态多轮 Case 实现说明

## 目标

让 Benchmark 在不超过 3 个用户回合内，既能保留原始固定挑战，又能自然回答
Agent 的实际追问；完整实际对话仍由八维 Judge 与指南 Judge 自动评分。

## 执行顺序

1. 发送 `conversation.opening`。
2. Agent 回复后，按顺序处理：
   - 由用户模拟模型根据 `reply_rules.when` 语义判断 Agent 是否在追问某项未披露事实；
   - Agent 提出未建模的合理追问时，调用用户模拟模型生成一致回复；
   - Agent 没有追问时，顺序发送 `follow_ups` 中尚未覆盖的原 Benchmark 挑战。
3. 到达 `max_turns`、没有下一条追问且模型未给出回复时结束。

## 运行态事实与复现

模型补全的 `new_facts` 写入当前 Case 的 `simulation_facts`，并按 Case 动态计划的
指纹缓存到 `outputs/.simulation_cache/`。后续重跑先复用这些事实，保持同一 Case
前后一致；详情页的“用户模拟路径”展示每轮来源与新增事实。

## 评分

- 固定八维仍全部评分，每维满分 5 分，医学安全性保持 0/5。
- 指南可写 `trigger`。Judge 先判断是否触发：未触发显示“未触发”，不扣分，也不计入
  指南覆盖分母；触发后按 `max_score - score` 从绑定维度扣分，最低为 0。
- `max_score` 仍是单条指南的最高扣分，不存在额外 Case 或维度级扣分上限。

## Case 设计约束

- 每题至多 3 个用户回合，至多 2～3 个主要测试点；长对话必须按主题拆分。
- 只注入与主题相关的稳定用户画像和 Timeline。
- 稳定已知事实被重复追问可在个性化维度扣分；时效性信息允许 Agent 再确认。
- 高风险事实应优先显式写进 `reply_rules`，并用 `when` 描述需要披露该事实的语义条件；模型补全不得与画像、Timeline 或前文冲突。
