# Recover Case Retry Progress

## Goal

- 单 Case 重试不依赖详情页驻留；离开后任务继续执行。
- 再次进入重试目标 Case 时，自动恢复进度条并继续轮询。
- 其他 Case 不误显示目标 Case 的重试进度。

## Data flow

1. 发起单 Case 重试时，在 `EvalRun.progress.context` 记录任务类型和 `sample_id`。
2. 进度接口把持久化任务上下文合并进当前进程的实时进度快照。
3. Case 详情页加载时查询进度，仅在上下文与当前 Case 匹配时恢复轮询。
4. 新发起重试必须等待服务端确认任务已进入队列后再开始轮询，避免把旧的 `success` 当成新任务完成。
5. 任务真正完成后自动重新加载 Case 明细；成功、失败或孤儿任务回收时清理持久化上下文。

## Verification

- 后端覆盖重试上下文落库、进度接口恢复与完成后清理。
- 前端覆盖目标 Case、其他 Case和已完成任务的识别边界。
- 运行前端类型检查、测试、生产构建及相关后端测试。
