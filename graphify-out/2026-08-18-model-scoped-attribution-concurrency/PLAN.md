# 归因任务按模型隔离并发

## 问题

归因任务当前共用一个进程级 3 槽信号量。较早任务会一次性创建全部 Case 协程，持续占用和排队这 3 个槽位，导致后创建任务即使使用不同模型，也会长期保持 0% 且所有 Case 都是等待中。

## 目标

- 每个判分模型配置独立拥有 3 个归因并发槽位。
- 同一模型的多个归因任务共享上限，避免绕过模型侧并发限制。
- 不同模型互不阻塞，例如 Kimi 与本机 Codex 可以各自并发执行。
- 保持逐 Case 状态、持久化队列和重启恢复逻辑不变。

## 实现

1. 将单一 `_global_semaphore` 改为按 `judge_model_id` 保存的 semaphore 映射。
2. `_run_item` 在等待槽位前读取任务绑定的模型 ID，再进入对应模型的并发限制。
3. 更新现有测试隔离逻辑，并增加同模型受限、不同模型可同时取得槽位的测试。

## 验证

- 归因任务服务测试通过。
- 完整后端测试通过。
- 检查不同模型信号量互不相同，同模型复用同一信号量。
